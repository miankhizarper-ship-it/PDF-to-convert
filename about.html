About FileTools

FileTools is a small collection of file utilities with one non-negotiable rule: your files never leave your device. Everything you see is HTML, CSS and JavaScript running in your own browser tab.

Why we built it

Most online file converters ask you to upload a document to somebody else's server, wait in a queue, and hope the retention policy is as short as advertised. For everyday tasks — turning a Word file into a PDF, joining two reports, shrinking a photo — that trade-off is unnecessary. Modern browsers can do all of it locally, at full speed, without a round trip.

So FileTools ships no backend at all. There is no upload endpoint, no worker queue and no database. When you drop a file here, it is read by your browser's File API and processed by an open-source JavaScript library running on your own CPU.

Your files never leave your device. All processing happens in your browser. You can confirm it yourself: open the Network tab in your browser's developer tools, use any tool, and you will see no request carrying your file.

How it is built

The site is plain HTML, CSS and JavaScript — no framework, no build step. Conversion work is handled by well-known open-source libraries loaded from a CDN and pinned to exact versions:

  • mammoth.js reads .docx files and turns them into HTML.
  • html2pdf.js paginates that HTML into a PDF.
  • SheetJS parses XLSX, XLS and CSV workbooks.
  • jsPDF with jspdf-autotable draws tables and text as PDF.
  • pdf-lib merges, splits and edits PDF page trees.
  • pdf.js renders PDF pages to images.
  • JSZip bundles multiple outputs into one archive.
  • qrcode-generator builds QR code matrices.

Every tool page loads only the libraries it needs, so the home page stays light. Object URLs are revoked after use, long conversions yield to the event loop so the interface keeps responding, and every failure path produces a message you can act on.

What we do not do

  • No accounts, no sign-in and no email address required.
  • No watermarks, no daily limits, no premium tier.
  • No document analytics — your files are never inspected by anyone but you.
  • No third-party advertising scripts.

Limits worth knowing

Client-side processing means the ceiling is your device, not a server plan. Very large files are held in browser memory, so a 400-page scanned PDF at maximum resolution can be slow or fail on a low-memory phone. The conversion libraries are fetched from a CDN on first load, so you need a connection for that first visit; after that the browser cache takes over.
